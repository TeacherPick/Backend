# 테스트 결과

검증일은 2026년 11월 25일이다. MySQL Community Server 8.4.9의 로컬 인스턴스에서 개발용과 테스트용 스키마를 분리했다. 실시간 API 검증은 Uvicorn에 HTTP와 WebSocket으로 연결해 수행했다.

| 검증 | 결과 |
| --- | --- |
| 개발 DB `teacherpick_dev`와 테스트 DB `teacherpick_test`에 Alembic 적용 | 둘 다 `0002`까지 적용 |
| 별도 업그레이드 스키마에서 `0001 → 0002` | 기존 한국어 계정명·프로그램, 강사 프로필 보존. 신규 컬럼의 NULL과 기본값 확인 |
| `alembic check` | ORM과 적용 스키마의 차이 없음 |
| 개발 데이터 초기화 | 강사·교사·프로그램·댓글·리뷰 생성. 재실행 시 기존 예시 데이터 유지 |
| 실제 서버 응답 | 홈, Swagger, OpenAPI, 정적 JS, 프로그램·강사 목록 및 MySQL 연결 상태 확인. Edge에서 Swagger의 API 목록 렌더링 확인 |
| Pytest | 실제 MySQL 기준 19건 통과. 회원·관리자 인증, 입력 검증 및 오류, 파일 첨부·삭제, 댓글과 답글, 추천, 리뷰, DM, DB 무결성, 마이그레이션 문서 추적 |
| SMTP | 로컬 TLS 서버에서 재설정 이메일을 받아 인증번호 검증, 새 비밀번호 로그인, 기존 세션 무효화 확인 |
| 브라우저 | Edge의 데스크톱·모바일 크기에서 교사·강사·관리자 계정 흐름, 게시물 파일 업로드 및 다운로드, 댓글·리뷰, 두 사용자 간 실시간 메시지 및 파일, 관리자 기능 확인 |
| 프론트엔드 구문·의존성 | 두 JS 파일의 `node --check`, 백엔드의 `pip check` 통과 |

초기 실행에서 ERD의 신규 컬럼 누락을 확인해 컬럼과 제약을 추가했다. 브라우저 검증에서는 댓글 본문과 숨은 수정 입력창을 같이 찾던 선택자 및 관리자 빈 목록 문구를 수정했다. TLS 메일 테스트는 숫자 뒤에 붙은 한국어 조사 때문에 인증번호를 추출하지 못해 숫자 경계 조건을 고쳤다. 각 수정 후 해당 테스트를 다시 실행했다.

운영 SMTP 제공자 연결, 배포 주소의 TLS, 실제 동시접속 규모의 부하, 이전 브라우저 미리보기 데이터 이관은 검증 범위에 포함되지 않았다. 수강 이력과 DM 차단의 출시 기준은 [요구사항 분석](requirements_analysis.md)에 근거와 현재 동작을 기록했다.

## 프론트엔드와 백엔드 저장소 분리 검증

2026년 11월 26일에 각 Git 저장소에 포함될 파일로 별도 실행 디렉터리를 구성했다. 백엔드에서 MySQL 기반 Pytest 20건과 Alembic 스키마 일치 검사가 통과했다. 프론트엔드와 API를 다른 Origin으로 실행하고 브라우저에서 회원·강사·관리자 시나리오를 모두 통과했다. 파일 업로드와 다운로드, 교사와 강사의 DM WebSocket 송수신도 검증했다.
